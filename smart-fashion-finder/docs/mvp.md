# StyleNear — הגדרת הצורך והפתרון (MVP)

> מסמך בסיס לגרסה הראשונה. כל פיצ׳ר חדש נמדד מול המסמך הזה לפני פיתוח.

## 1. הבעיה (במשפט אחד)

ראיתי בגד שאהבתי (ברשת / ברחוב / אצל חברה) — אבל אני לא יודע/ת **איפה לידי יש אותו בחנות פיזית, במידה שלי, ובמלאי עכשיו**.

## 2. למי זה מיועד

| | |
|---|---|
| **קהל** | קונים בפיילוט חיפה שרוצים לבדוק מידה וצבע בחנות, לא רק להזמין אונליין |
| **אזור** | חיפה · גרנד קניון וסביבה (ואז הרחבה לשכונות נוספות) |
| **לא ל־v1** | קונים בכל הארץ, מסחר B2B לחנויות, משלוחים לבית |

## 3. ההבטחה של StyleNear

**מצאת את הבגד → בודקים מלאי ומידה לידך → הולכים לחנות.**

זרימה אחת ברורה:

```
בגד (צילום / בחירה) → זיהוי בסיסי → חנויות עם המידה שלי → ניווט / קשר לחנות
```

## 4. מה חייב להיות ב־MVP (In scope)

| # | תכונה | למה זה ליבה |
|---|--------|-------------|
| 1 | **הזנת פריט** — צילום, גלריה, או בחירה מהבובה/קטלוג | בלי פריט אין חיפוש |
| 2 | **זיהוי בסיסי** — קטגוריה, צבע, תת־סוג (+ מידה מועדפת של המשתמש) | כדי להתאים למלאי |
| 3 | **חנויות קרובות עם מלאי** — שם, מרחק, מחיר, מידות, האם יש את המידה שלי | זה הערך העסקי |
| 4 | **פעולה לסגירה** — ניווט למפות; ב־v1 גם WhatsApp לחנות (“יש מידה?”) | בלי זה האפליקציה רק מציגה מידע |
| 5 | **פרופיל קצר** — מידה קבועה + אזור פיילוט | חוסך שלבים בכל חיפוש |

### הגדרת “הצלחה” למשתמש אחד

תוך פחות מ־2 דקות: המשתמש מזהה פריט → רואה לפחות חנות אחת עם המידה שלו → לוחץ ניווט או שולח הודעה לחנות.

## 5. מה לא נכנס ל־MVP (Out of scope)

נדחה במכוון לגרסאות הבאות:

- הלבשה פוטוריאליסטית מושלמת / try-on AI מתקדם
- SALE, באנרים שיווקיים, קולקציות דקורטיביות
- התראות “המידה חזרה למלאי”
- פאנל מלא לבעל חנות (אלא אם נדרש ידנית לפיילוט)
- תשלום באפליקציה / הזמנה אונליין
- חשבון משתמש עם התחברות (מספיק שמירה מקומית)
- כיסוי ארצי מעבר לחיפה

## 6. עקרונות מוצר

1. **מסלול אחד** — כל מסך משרת את הזרימה בגד→חנות; לא מרקטפלייס אופנה כללי.
2. **מידה קודם** — חנויות עם המידה של המשתמש מקבלות עדיפות ויזואלית.
3. **פיילוט קטן אמיתי** עדיף על דמו גדול ריק — מעט חנויות עם מלאי אמין.
4. **עברית + RTL** בכל ממשק המשתמש.

## 7. מה כבר קיים בקוד מול מה חסר

| תכונת MVP | סטטוס בקוד היום | הערה |
|-----------|-----------------|------|
| הזנת פריט (צילום/גלריה/בובה) | חלקי | UI קיים; זיהוי mock |
| זיהוי בסיסי | חסר אמיתי | `useGarmentRecognition` מחזיר נתוני דמו |
| חנויות + מידה | חלקי | `inventory.json` + סינון מידה; מלאי לא חי |
| ניווט לחנות | קיים | קישור Google Maps ב־`StoreCard` |
| WhatsApp לחנות | חסר | עדיפות גבוהה ל־MVP |
| מידה קבועה + אזור | קיים | AsyncStorage + מסכי פרופיל/אזור |
| שעות פתיחה | חסר | מומלץ מיד אחרי WhatsApp |

## 8. סדר פיתוח מומלץ אחרי המסמך

1. חיבור זיהוי תמונה אמיתי (או תיוג ידני חכם כשלב ביניים)
2. מודל מלאי: פריט × חנות × מידה (גם אם עדיין ידני לפיילוט)
3. כפתור WhatsApp / “שמרו לי את הפריט”
4. שעות פתיחה + “פתוח עכשיו”

---

**סיסמה פנימית:** אם פיצ׳ר לא עוזר למשתמש להגיע לחנות עם המידה שלו — הוא לא ב־MVP.
